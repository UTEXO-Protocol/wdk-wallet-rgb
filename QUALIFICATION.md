# On-chain RGB SDK qualification register

The candidate is a private on-chain SDK for Node and Bare. Mainnet and Public Signet admit Bitcoin and ordinary RGB under the network policies in the [candidate guide](CANDIDATE.md). Regtest, Dev and staging have separate service and bridge policies. This register contains deployment-specific test evidence and stays in the repository outside the package.

## Alpha.24: unmodified BFA.8 adapter

The adapter now compiles against stock BFA.8 `2f7b21d8637baad548504ea870deb2c0d4d0a37d` (tree `5492824f3cf47b4c821dfca8b7a63fed27858486`). All eight historical RGB overlays remain removed, and the separate Electrum and Esplora client patches are removed too. The graph retains the same BFA.8 source and its required protocol revisions. Source preparation no longer requires APIs that only existed in those patches.

NIA/CFA issuance follows wallet admission on Mainnet, Regtest, and Public, Dev and staging Signet. WDK uses stock Esplora for Dev and owns genesis/block-one preflight at its connection and network-operation boundaries. Issuance consistency rescans preserve the admitted EVM RPC configuration, mint-lock windows and proxy credentials. BTC-only mode continues to exclude RGB operations.

Expired exact-recipient NIA/CFA cancellation now uses the public refresh and transactional `fail_transfers` APIs. It rejects active, BFA, assetless and progressed invoices and rereads the result. Its retention/proxy-loss semantics are those of BFA.8, not the stronger authenticated-empty-proof rule of the removed patch.

Before handing a signed RGB send or burn to the library, WDK durably records the exposed inputs. Later transaction plans cannot reuse them after an ambiguous failure. Issuance and blind receive also check any empty colored allocation candidates against those records. Stock Electrum may retransmit the same signed bytes; SDK recovery does not prepare or sign another transfer. The input journal must be preserved with the wallet state.

## Alpha.22 manual receive and cancellation

An expired ordinary RGB receive may be cancelled by exact batch index and recipient ID. Native admission checks the stored invoice and asset schema, the local transfer state, the colored wallet indexer, the clock on each configured recipient proxy and a fresh authenticated list response. A verified empty response can release the reservation. Unavailable, ambiguous or nonempty responses keep it reserved. If the proxy has already pruned the invoice, the wallet cannot verify the empty result required to cancel it. BFA and invoices without an identified asset remain protected because an accepted mint can outlive invoice expiry. This operation produces no signature, transaction or fee. A retry against the same cancelled receive is idempotent.

The packed macOS ARM64 Node and Bare runtimes created and decoded both 24-hour, amountless invoice types and settled funded NIA and CFA transfers at six confirmations. The cancellation matrix covered all eight combinations of runtime, schema and recipient type. The test advanced the expiry of an exact disposable invoice with the wallet closed, then exercised the production cancellation operation with real local Bitcoin and proxy services. A successful empty proxy response released the reservation, another invoice was unaffected, and reopen preserved the cancellation. Active, mismatched, locally attached, pending, retrieved, malformed, ambiguous and unavailable cases retained the reservation. Fixed and amountless BFA and assetless invoices stayed protected after expiry.

The SDK passed 58 JavaScript tests, public types and 38 native tests. Two issuer-fixture-dependent tests remain opt-in. The candidate keeps the BFA.7 source and checked Electrum reconnect overlay.

## Current release dependencies and application work

The alpha.24 records at the top of this file supersede the historical application and dependency statements above. Earlier Iris APKs contain patched SDK versions; none is qualified as an unmodified alpha.24 application.

- **Contract registration.** Stock BFA.8 cannot preregister the validated USDT genesis used by Iris. Port the public import API proposed in [RGB-Tools #103](https://github.com/RGB-Tools/rgb-lib/pull/103) into the compatible BFA branch. Real generic receive works without that API; it does not provide asset-pinned preregistration.
- **Hosted settlement.** Use deployment-approved asset metadata, proxy, gateway, signer and contract versions as one compatible system. Local mint and proof validation do not establish a hosted payout. No hosted bridge was operated for alpha.24. The SDK contains no Dev USDT export or asset metadata.
- **Dependency advisories.** The exact locked Rust audit has eight findings and the existing `unsafe-libyaml` maintenance warning; see the alpha.24 table and [audit receipt](qualification/alpha24/dependency-audit.json). The runtime npm audit is clean. A compatible upstream TLS/SQLite graph is still needed for a clean Rust release audit. Source-file patches have not been restored to hide these findings.
- **Tether Core integration.** Core beta.23 registration and replacement middleware pass actual Node and Bare qualification. Beta.22's built-in policy API is tested separately; it is not a beta.23 API. Core disposal remains synchronous, so applications must explicitly await the RGB account's shutdown before disposing Core or replacing the wallet. The [typed integration recipe](CANDIDATE.md#tether-wdk-core) bridges Core's broad constructor constraint without making RGB configuration optional.
- **RGB recovery and VSS.** A seed restores keys and discoverable Bitcoin history, not missing consignments or operation journals. Preserve complete RGB state. The on-chain SDK has no automatic external-signer VSS snapshot/restore implementation; wallet startup and transactions do not depend on VSS. No removed output-provenance or URL-policy overlay remains in this build.
- **Application and device acceptance.** All eleven Bare targets and five Node workers have separate build records. Desktop packed execution and mobile ABI checks have different scopes. Iris remains unchanged and needs the Bare 1.37.1 runtime integration, rebuilt application packages and device acceptance before adopting alpha.24. Historical Iris PIN, biometric and bridge results do not substitute for those checks.
- **Public release.** Complete funded public-network and hosted payout acceptance, application/device acceptance, third-party notices and redistribution review. Choose an explicit breaking-version or distribution strategy before replacing the published package, whose API and wallet identity differ from this candidate. This remains a private review candidate; no merge or publication has occurred.

Ambiguous operation records remain bound to the original wallet and request. Preserve their journals and reconcile the original transaction; do not edit them or submit a replacement spend to bypass uncertainty. An expired receive may be cancelled only through the exact public API described above. Stock proxy-retention semantics and independent upstream resolver behavior are deliberate, documented limits of this unmodified-library build.
