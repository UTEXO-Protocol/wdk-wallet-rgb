# On-chain RGB SDK qualification register

The candidate is an on-chain SDK review branch for Node and Android Bare. It remains private while the release gates below are open. It admits isolated Regtest for Bitcoin and RGB, plus separate Bitcoin-only and staging RGB profiles for public Signet.

## Current dependencies

The alpha.7 qualification below used Tether base wallet `1.0.0-beta.25` and RGB BFA `.5` with the locked Electrum graph. Its Android worklet used Bare Kit `3.0.1` and Bare `1.36.2`. Tether WDK core `1.0.0-beta.22`, Pear worker `1.0.0-beta.17`, React Native core `1.0.0-beta.23`, and WebRGB WalletConnect `0.1.3` were checked separately. They describe the host integration and transport, which have their own compatibility gates. The alpha.8 Dev Esplora scope and local tests are documented in the [native runbook](native/README.md#dev-checkpoint-candidate).

## SDK and Iris contract

| Area | Candidate SDK surface | Remaining Iris integration or qualification |
| --- | --- | --- |
| Wallet lifecycle | Explicit offline open and connect, awaited shutdown, account-path support, read-only WDK policy account, stable session address and explicit rotation | Bind the IPC approval ticket to the app's authenticated wallet generation. Close approval admission and await wallet shutdown before Pear resets. |
| BTC and RGB | Exact base-unit amounts, BTC receipts, blind and witness invoices, decoded invoice and transfer status, assets, balances, refresh outcomes and configured Electrum and proxy checks | Adapt legacy field shapes and amount types. Distinguish cached reads, session state and actual deployed-service readiness. |
| RGB output setup and spends | Prepare, commit, cancel and explicit pre-Begin and post-submission recovery with the original operation ID | Keep distinct UI for ambiguous state, a safely released unsigned reservation and an observed submitted transaction. |
| BIP-322 | Explicit message approval, owned P2TR signing, P2TR/P2WPKH simple verification | Connect app step-up approval and qualify the resulting production worklet and physical devices. |
| WebRGB | Request-scoped facade, explicit V1 payout route and asset allowlists, durable invoice and burn identity, proof scoping and recovery | Qualify the actual session transport, persistent grants, lifecycle and request identity with the app. Verify every advertised route end to end. |
| VSS | Startup and on-chain operations have no VSS dependency | Existing VSS stays optional. Its external-signer backup and recovery require separate qualification. |

The legacy package and the new engine have different public contracts and can derive different wallet identities from the same recovery phrase. Use distinct storage for qualification. A future public release needs an explicit breaking-version or distribution decision before replacing the published package.

## Upstream and service dependencies

1. **Hosted assets and protocol.** The existing public Signet staging USDT export uses an earlier BFA schema. Its Genesis commits to that schema, so re-encoding its bytes cannot make it compatible with the schema in this SDK. The upgraded staging profile needs an official export for a new issuance with a new asset ID, together with the exact asset metadata and export SHA-256. Verify the deployed gateway, signer, RGB proxy and Arbitrum contract as one versioned system. The contract must expose finalized mint lock records through `getFundsInBlock`. The candidate includes narrow contract-registration and mint-conservation overlays while those patches await upstream acceptance. [RGB contract import](https://github.com/UTEXO-Protocol/rgb-lib-bfa/pull/4) · [Mint conservation](https://github.com/UTEXO-Protocol/rgb-lib-bfa/pull/8) · [Gateway migration](https://github.com/UTEXO-Protocol/bridge-utexo/pull/531) · [Signer migration](https://github.com/UTEXO-Protocol/enclave-signer/pull/337) · [Bridge contracts](https://github.com/UTEXO-Protocol/bridge-smart-contracts/pull/185)
2. **Public Signet staging.** Both Signet profiles pin `ssl://electrum.iriswallet.com:50033` with certificate validation and verify genesis and the public Signet block-one hash. Staging RGB also pins `rpcs://staging.rgb-proxy.utexo.com/json-rpc` and `https://arb1.arbitrum.io/rpc`. The native egress overlay checks DNS at connection time and disallows redirects and system proxies for RGB proxy, reject-list and EVM RPC requests. Iris keeps the staging asset and bridge admission closed pending a compatible asset export and a matching deployment. Funded local fixture results cover the local codec and proof recovery. Hosted payout needs its own funded test. [RGB SDK endpoints](https://github.com/UTEXO-Protocol/rgb-sdk-rn#rgb_l1-connection)
3. **VSS and RGB restore.** Explicit BTC-only restore discovers same-engine Bitcoin within the HD scan gap and keeps RGB mutations disabled in that directory. RGB ownership needs matching client-side state. External-signer VSS needs consistent snapshot capture and acknowledgement on the current RGB graph, authenticated storage, and a restore path that validates the wallet identity and RGB state before admitting mutations. The SDK starts and transacts independently of VSS. [Snapshot proposal](https://github.com/UTEXO-Protocol/rgb-lib-bfa/blob/abd41d3afff6d8fb11461e26e843301650e22df3/docs/contract-registration-and-snapshots.md)
4. **Stock Tether lifecycle and Expo support.** WDK Core `dispose()` and Pear's default reset do not await async teardown. A host-owned path can await explicit SDK shutdown. Stock reset needs an upstream lifecycle contract before reuse. The current React Native core declares `expo-crypto >=55 <57`, outside Iris's Expo 57 graph. [WDK Core](https://github.com/tetherto/wdk/blob/c8a252fa127d9fc4a580252d3e46b4eaf372315a/src/wdk.js#L331-L342) · [Pear reset](https://github.com/tetherto/pear-wrk-wdk/blob/953af3cf7bf4ada33cc66e63185d1bdcf70d427b/src/handlers/lifecycle.js#L248-L268) · [React Native core peers](https://github.com/tetherto/wdk-react-native-core/blob/30fc571d00b19839476c32a919356087711c5c7d/package.json)
5. **Dependency maintenance.** The locked Rust graph has an unmaintained `unsafe-libyaml` dependency via `rgb-strict-types` and `serde_yaml`. Resolve it through a compatible upstream graph or a separately reviewed patch. The local audit reported zero known vulnerabilities in the locked graph.

## Remaining SDK, app and qualification work

- **Incident handling.** Native journal writes share the wallet directory lock. Legacy ambiguous records, orphaned unsigned preparation files and a submitted operation with insufficient evidence to resolve its fate still require an operator procedure. Never edit the journal to bypass an unresolved spend.
- **Product worklet and transport.** Adapt Iris's legacy types, optional capabilities and network names, apply authenticated approval and awaited shutdown, and qualify actual WalletConnect and bridge lifecycle. Core policy conditions get a read-only view. Function-bearing trusted WebRGB requests need a separate local dispatch boundary because Core policy snapshots serializable arguments. The typed SDK signer intentionally limits spends to reviewed native plans.
- **Acceptance and distribution.** Qualify the final product on iOS and physical devices, and perform funded Signet and hosted payouts after service prerequisites are available. A checked Android addon and packed SDK do not qualify a product APK. Complete release artifact attestation, third-party notices and distribution-rights review, and the public breaking-version decision. The local build inventory records declared licenses and notice hashes, with further redistribution review for embedded dependencies and platform runtimes.
