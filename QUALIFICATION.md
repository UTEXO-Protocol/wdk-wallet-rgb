# On-chain RGB SDK qualification register

The candidate is a private on-chain SDK for Node and Bare. Mainnet and Public Signet admit Bitcoin and ordinary RGB under the network policies in the [candidate guide](CANDIDATE.md). Regtest, Dev and staging have separate service and bridge policies. This register contains deployment-specific test evidence and stays in the repository outside the package.

## Proxy expiry and acknowledgement hardening (alpha.13)

The candidate adds a narrow BFA.7 overlay for untrusted proxy timing, overflow-safe deadline checks and conservative handling of ambiguous positive acknowledgement responses. Invalid or missing timing keeps the affected transfer and its reservations pending. A later valid response or chain evidence can reconcile the original transfer; recovery repeats its signed acknowledgement or saved transaction, without a new spend request. Existing network guards are retained.

The exact admitted source passed five policy tests and the real loopback proxy/SQLite fixture, including malformed replies, repeated refresh, saved deadline corruption, reservation retention across reopening, and same-acknowledgement repair. A forged expired-operation response cannot release a valid future reservation; cleanup requires the local broadcast deadline and full confirmation margin, after the chain checks. Ten independently compiled boundary tests also passed. The adapter passed 23 native/checkpoint tests; one existing optional test requires a separately recovered historical Dev artifact. All 50 SDK tests and TypeScript checks passed. The [native test command](native/scripts/check-proxy-deadline.py) uses distinct fixture package identities; its test-only code is excluded from the production addon. These scopes do not establish arbitrary crash recovery: process death after remote ACK acceptance but before the existing local transaction commits remains an inherited durability window. The upstream protocol's separate late-broadcast risk after its legitimate local cutoff also remains.

The rebuilt Android ARM64 addon SHA-256 is `e0461bc3422dc8e4ee9779ce0ddda1d068b8ae73492cc6a605981f014719b914`, functional source tree `d9de67fe9a2512106afd054977a1e32abb9a1184`, Bare tree `5408b3e56cdb7604316b094aa69ffb2d30513189`. ELF admission verifies 16 KiB load/RELRO alignment, NX stack, immediate binding, NODELETE, exact exports/dependencies and compatibility with the unchanged Bare Kit runtime. Source/native checks, packed-host transfers and Iris APK acceptance have separate evidence below.

## Upstream and service dependencies

1. **Hosted assets and protocol.** The existing public Signet staging USDT export uses an earlier BFA schema. Its Genesis commits to that schema, so re-encoding its bytes cannot make it compatible with the schema in this SDK. The upgraded staging profile needs an official export for a new issuance with a new asset ID, together with the exact asset metadata and export SHA-256. Verify the deployed gateway, signer, RGB proxy and Arbitrum contract as one versioned system. The contract must expose finalized mint lock records through `getFundsInBlock`. The candidate retains standalone contract registration. BFA.7 enforces mint conservation and uses a separate lock identifier tied to the mint transaction. ## Remaining SDK, app and qualification work

- **Incident handling.** Native journal writes share the wallet directory lock. Legacy ambiguous records, orphaned unsigned preparation files and a submitted operation with insufficient evidence to resolve its fate still require an operator procedure. Never edit the journal to bypass an unresolved spend.
- **Product worklet and transport.** Iris's on-chain adapter, authenticated approval, awaited shutdown and separate trusted WebRGB dispatch are implemented and locally exercised. Core policy conditions get a read-only view; the typed SDK signer limits spends to reviewed native plans. Broader device, relay, network and payout-route acceptance remains separate from the recorded local transport cases.
- **Acceptance and distribution.** Qualify the product on iOS and physical devices, and perform funded Signet and hosted payouts after service prerequisites are available. Preserve the distinction between the funded Android APK and later presentation-only builds. Complete release artifact attestation, third-party notices and distribution-rights review, and the public breaking-version decision. The local build inventory records declared licenses and notice hashes, with further redistribution review for embedded dependencies and platform runtimes.
