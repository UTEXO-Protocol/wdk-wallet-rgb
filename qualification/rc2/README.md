# Version 3.0.0-rc.2 qualification

The tested complete npm archive was packed from `2e53b9f65ac7a40573311408bb0ab850e626d133`, using native producer `49a19de14046f778241a89a3e16483521fd393cc`. It contains 41 files and all eleven Bare targets, is 203,881,548 bytes, and has SHA-256 `2c6c74ddbffb33af0bbe8ca87ac6f3aceb0e25823a334309d5531b3f1d4c95ff`. Five Node workers are separate CI artifacts. Qualification-only commits do not change these identities.

- [Platforms](platforms.json): all sixteen CI binaries were admitted against producer, lockfiles, archive digests, binary hashes and ABI receipts. All 19 producer jobs passed. Nine desktop targets executed packed consumers; seven mobile targets passed build/ABI checks only.
- [Funded host results](funded-host.json): the actual full archive and its CI-built Node/Bare Darwin ARM64 artifacts pass six BFA mint receives and ten V1 burns. Four mints exercise blinded/witness verification before EVM payment, including a complete process restart. All five configured route commitments and exported proofs are independently checked; interrupted final acknowledgement recovers the original burn without another Begin/End.
- Eight generic invoice creation/decode cases cover both runtimes, both invoice kinds and optional amounts. The invoice's native asset ID and schema stay null; the separately persisted expected asset never becomes an invented invoice commitment.
- Eight negative proof cases cover corrupt data, a valid proof for another mint of the same asset, an oversized proof and a symlink. Each case restores the exact original bytes and succeeds, demonstrating that verification does not reuse a cached successful result.

Verification binds the exact owned invoice, recipient, actual asset, witness, operation and LockId before returning the amount, chain, bridge and exclusive payment deadline. Foreign wallets, changed public keys/proxies/expiry/query order and contradictory expected assets are rejected. Verification neither pays the EVM lock nor invokes an outgoing wallet spend. A new authorized topic may verify its own wallet's manually pasted invoice; burn proof recovery remains bound to the original authorization scope.

The fixture uses isolated Regtest, Anvil chain 31337 and a normal-retention protocol-1.0 proxy. The clock offset was zero at admission. Its independent compatible BFA.7 issuer/proof validator is distinct from the SDK's unmodified BFA.8 runtime. Public receipt projections and original evidence hashes are recorded here; seeds, complete wallet state and raw proofs stay outside the repository.

Stock BFA.8 retains its initial checked-mint semantic decision. Re-reading and binding that proof is not a new issuer reject-list freshness guarantee. Before paying, the caller must compare `beforeBlock` with the current EVM block. Expired invoices cannot obtain new payment verification; completion of an already accepted incoming transfer follows native status.

These results do not establish Android/iOS application or device acceptance, hosted Dev behavior, or live Ethereum, Arbitrum, Polygon, Plasma or Tron payout settlement. RC1 ordinary RGB, Core/BTC and BIP-322 funded results and alpha.24 cancellation/retention tests retain their original version identities; they are not relabeled as RC2 runs. Standalone contract import, automatic VSS restore and RGB recovery from seed alone remain outside the provided API scope.
